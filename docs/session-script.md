# 시연용 세션 기록(JSONL) 만들기

XHuman의 **입력 데이터**인 Claude Code 세션 기록을 만드는 절차다. 화면 녹화 영상과는 무관하다. Claude Code로 샘플 프로젝트를 실제로 개발하면 `~/.claude/projects/` 아래에 대화 기록 JSONL이 자동으로 남고, 그 파일이 시연 데이터가 된다.

## 원칙

- **실제 세션만 쓴다.** JSONL을 손으로 만들거나 대화 내용을 고치지 않는다. 이 제품의 핵심 주장("인용이 실제 기록에 없으면 저장하지 않는다")과 모순되고, 심사에서 "실제 세션인가요?"에 "예"라고 답할 수 없게 된다.
- 허용되는 편집은 경로·사용자명 치환과 비밀값 가리기뿐이다.
- 길게 자유롭게 개발하지 말고, 장면을 유도하는 대본으로 40~60분 녹화한다. 짧아야 분할 없이 한 번에 추출되고 결과 편차가 작다.

## 1. 준비

- [x] 빈 폴더 `demo-payment` 생성, `git init`, 요구사항만 적은 `README.md`로 첫 커밋
- [x] Claude Code 버전 고정 확인(해커톤 당일 버전과 같게)
- [x] `pytest` 설치. Claude Code가 `pytest`를 실행할 수 있게 허용(이전 픽스처는 실행 권한이 없어 실패 테스트가 남았다)
- [x] 편집은 자동 승인으로 둔다. AI가 제안한 편집을 손으로 고치지 않는다(`userModified`는 미검증 필드)
- [x] 세션 하나로 끝까지 간다. `/clear`, `/compact`, 세션 재개, 서브에이전트 사용 금지

README 내용 예:

```
# demo-payment
PG 결제 API를 호출하는 모듈. payment/retry.py에 charge_with_retry(client, order)를 둔다.
client.charge(order_id, amount, idempotency_key, timeout)가 응답(status_code, headers, json())을 돌려준다.
```

## 2. 대본

사용자 발화는 아래 문장을 그대로 쓴다. 대본에 없는 말로 장면을 억지로 유도하지 않는다. 그 발화도 기록에 남아 결정 주체 분류가 바뀐다.

| 턴 | 사용자 발화 | 노리는 장면 | 확실성 |
|---|---|---|---|
| 1 | PG 결제 API를 호출하는 charge_with_retry(client, order) 함수를 payment/retry.py에 만들려고 해. 코드를 쓰기 전에 재시도 정책을 어떻게 할지 먼저 짧게 제안만 해줘. | AI가 결정 여러 개를 한 번에 제안 | 높음 |
| 2 | 좋아 그렇게 해. 타임아웃(timeout) 값은 PG사 문서를 아직 못 봐서 나중에 정하자. 테스트도 같이 만들어 줘. 최대 3회 시도는 테스트로 꼭 확인해. | 포괄 수락 + **보류**. `client.charge`가 `timeout` 인자를 받으므로 AI가 기본값을 넣을 수밖에 없다 → `deferred`. 뒷부분은 5턴 테스트 변경의 밑밥 | 높음(포괄 수락), 중간(보류: AI가 타임아웃을 상수 없이 인자 기본값으로 숨기면 추출이 놓칠 수 있음) |
| 3 | pytest 돌려서 통과하는지 확인해 줘. | 녹색 확인. **통과하면 세션 밖 터미널에서 직접 커밋** | 높음 |
| 4 | 멱등성 키는 order.id 기반으로 고정해. 재시도마다 새로 만들면 이중 결제가 날 수 있어. | 사람 지시(이유 포함) | 높음 |
| 5 | 최대 시도 횟수를 2회로 줄여 줘. | AI가 기존 테스트의 `assert len(...calls) == 3`류를 고침 → `assertion_changed` | 높음 |
| 6 | 4xx는 재시도하지 말고 status_code를 가진 PaymentDeclined를 던지게 해 줘. | AI가 429를 스스로 예외로 둠 → AI 단독 | 중간(프로토타입에서 나옴). **11/10 녹화: 409·429도 함께 재시도에서 빠졌고 AI가 409 위험을 경고, 사람은 넘어감** |
| 7 | 결제가 성공하면 sqlite payments 테이블에 기록하는 record_payment 함수를 추가해 줘. | `db_write` 위험 태그, 트랜잭션·중복 처리 등 AI 단독 결정 | 중간 |
| 8 | 테스트 전부 돌려서 통과시켜 줘. | 최종 코드 녹색 → 직접 커밋 후 세션 종료 | 높음 |

3턴과 8턴 뒤의 커밋은 Claude Code가 아니라 사용자가 별도 터미널에서 한다. 테스트 변경 감지는 대화 기록의 `Edit`만 보므로 3턴 커밋이 없어도 감지에는 지장이 없다(11/10 정정). 샘플 프로젝트는 대화 기록의 `Write`·`Edit`를 순서대로 적용해 복원할 수 있고, 이 방법이 작성 출처와 가장 확실히 맞는다.

AI 응답은 매번 다르다. **2회 녹화해서 장면이 더 잘 나온 쪽을 고른다.**

결정 17개(주체별):

- 보류 후 반영: ① 타임아웃 기본값을 정하지 않고 `None`+TODO ② 타임아웃이 없으면 PG를 호출하지 않고 `ValueError` ③ **오탐:** "타임아웃·연결 오류와 500/502/503/504만 재시도". 보류 절과 "타임아웃" 한 단어만 겹쳐서 보류로 잡혔다. 실제로는 1턴 포괄 수락과 6턴 사람 지시의 결과다.
- 포괄 수락: 확정 실패/결과 불명 예외 분리, full jitter 백오프(상한 8초), 30초 마감, sleep·난수·clock 주입
- AI 단독: `PaymentDeclined`를 `ChargeFailed` 하위로, 4xx 아닌 예상 밖 코드(501)는 `ChargeFailed`, 재시도 예외를 `TimeoutError`·`ConnectionError`로 한정, store.py 분리·`charge_with_retry`와 미연결, `order_id` UNIQUE·중복 무시, 2xx 아니면 `ValueError`, 응답 전체를 JSON으로 저장
- 사람 지시: 멱등키 `charge-{order.id}`, 최대 2회, 4xx→`PaymentDeclined`

알려진 한계(발표 한계 장표에 반영):

- **지시의 부수 효과를 못 잡는다.** "4xx는 재시도하지 마"로 409·429 재시도와 Retry-After 처리가 사라졌고 AI가 409 위험을 경고했지만, 이 결정은 "사람 지시" 하나로 묶였다.
- **보류 판정이 키워드 한 단어에 기댄다.** 위 ③ 오탐. 같은 이유로 ②는 영어 `timeout` 한 단어로 잡혔다. 2개 이상 겹침을 요구하면 ①②도 빠지므로 규칙을 바꾸지 않는다.
- AI가 테스트의 의미를 바꾼 것(5턴 마감 테스트: 마감 30→20초, 기대 호출 2→1)은 결정으로 뽑히지 않는다. 테스트 변경 감지가 맡는다.
- 실행 편차는 아직 재지 않았다(1회 실행).

**보류가 안 잡힐 때** (2회 녹화 모두 `deferred` 0개)

1. 추출 결과에 타임아웃 결정 자체가 없으면: extract 프롬프트 규칙 9 끝에 "사용자가 나중으로 미룬 사항을 AI가 기본값으로 채웠다면 그것도 별도 결정으로 뽑는다"를 한 줄 넣고 버전을 v0.4로 올린 뒤 같은 세션으로 다시 추출한다. 편차 측정(build-plan 0장 15:00)은 v0.4로 한다.
2. 타임아웃 결정은 있는데 주체가 다르면: 결정 요약과 보류 절이 핵심 단어를 공유하는지 본다(`타임아웃`/`timeout`). 분류 규칙을 고칠 문제이지 대화를 고칠 문제가 아니다.
3. 대화나 JSONL을 손으로 고쳐서 보류를 만들지 않는다(원칙 1).
4. 1번(v0.4 한 줄)은 시연 장면을 살리려는 조정이라 회색 지대다. 쓰게 되면 이전 3턴 세션에서도 결과가 나빠지지 않는지 확인하고, 발표 한계 장표에 "보류 추출 규칙을 시연 세션을 보고 한 줄 보강했다"고 밝힌다. 11/10 녹화본은 v0.3 그대로 보류가 잡혀 쓰지 않았다.
- [ ] 만료 장면용 수정은 세션에 넣지 않는다. 발표 때 손으로 한 줄 고친다([demo-script.md](demo-script.md) 장면 5)

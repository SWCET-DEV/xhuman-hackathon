# XHuman (Explainable Human) — 해커톤 기획서

> 코드 에이전트로 혼자 빠르게 개발하는 내가 "좋아"로 넘기고 "나중에"로 미룬 결정, 곧 **사람이 정하지 않은 결정**을 대화 기록에서 찾아 필요할 때 3분 만에 **내가 설명할 수 있게** 만드는 XHuman

## 1. AI로 해결하고자 하는 문제 상황 또는 새롭게 시도해보고 싶은 업무/서비스는 무엇인가요?

- **제가 필요해서 만들기 시작했습니다.** 저는 5~6년 동안 프로젝트를 수행했지만, 한동안 개발에서 손을 놓았다가 코드 에이전트로 혼자 방대한 양을 개발하게 됐습니다. 정신없이 개발하다 보니, 돌아보면 이해하지 못하는 코드가 산더미였습니다. 경력이 있어도 에이전트가 만드는 속도로는 모든 코드와 흐름을 이해할 수 없고, 결국 AI의 제안을 "좋아"로 넘기고 모르는 건 "나중에"로 미루게 됩니다.
- AI 코딩 도구가 코드를 만드는 속도를 사람이 이해하는 속도가 따라가지 못하고 있습니다. AI가 만든 코드는 테스트를 통과해도, 작성자가 "왜 이렇게 했는지", "요구사항이 바뀌면 어디를 고쳐야 하는지" 설명하지 못하면 리뷰와 인수인계가 멈춥니다. 경력자도 피하기 어렵고, 신입일수록 더 심합니다. Anthropic 내부 조사(2025, 엔지니어 132명)에서도 업무의 약 60%에 AI를 쓰지만 완전히 맡길 수 있는 일은 0~20%였고, AI를 감독하려면 감독할 이해가 남아 있어야 한다는 "감독의 역설"이 지적됐습니다.
- 특히 위험한 것은 **사람이 정하지 않았는데 코드가 된 결정**입니다. AI가 여러 결정을 한꺼번에 제안하면 "좋아, 그렇게 해" 한마디로 모두 넘어가고, "그건 나중에 정하자"고 미룬 값도 AI가 기본값으로 채워 코드에 넣습니다. 대화에도 코드에도 "아직 아무도 정하지 않았다"는 표시는 남지 않습니다.
- "왜"에 대한 답은 코드가 아니라 AI와 나눈 대화 안에 있는데, 세션이 끝나면 함께 사라집니다. 기록 파일이 남아 있어도 특정 함수의 결정 근거를 찾아 읽는 사람은 거의 없습니다.
- 업계는 이 현상을 **"이해 부채(Comprehension Debt)"**라고 부릅니다. Anthropic의 무작위 대조 실험(2026, 개발자 52명)에서 새 라이브러리를 AI와 함께 익힌 집단은 직후 퀴즈 점수가 17%p 낮았고(50% 대 67%), 격차는 디버깅 문항에서 가장 컸습니다. 반면 AI로 코드를 만든 뒤 질문으로 이해를 확인한 소수 참가자는 높은 점수를 보였습니다. XHuman은 이 "만든 뒤 확인"을 개인의 습관이 아니라 도구로 만드는 시도입니다. 모든 코드를 이해시키겠다는 도구가 아닙니다. 사람이 정하지 않은 결정이 어디 있는지 알려 주고, 필요할 때 그 부분만 내가 설명할 수 있게 만듭니다.

## 2. 제안한 아이디어를 실현하기 위해 AI를 어떻게 활용할 계획인가요?

- **원칙:** "설명은 적게, 질문으로 확인하고, 모르는 부분만 채우기". 설명을 다시 읽기보다 스스로 답을 떠올려 볼 때 이해가 오래 남는다는 인출 연습 원리를 적용합니다.
- **역할 분담:** AI는 결정 추출, 질문 생성, 답변 판정, 보충 설명만 합니다. 함수 식별·변경 감지·작성 출처·위험 태그·결정 주체·점수는 프로그램이 계산합니다. 그래서 AI가 지어낸 근거는 원문 대조로 걸러지고, 점수는 항상 같은 규칙을 따릅니다.
- **축적:** AI가 개발 대화에서 핵심 결정, 이유, 버린 대안을 근거 원문과 함께 추출해 Python 함수 단위로 연결합니다. 원문과 일치하는 인용만 근거로 인정합니다. 결정 주체는 사람 지시 / 포괄 수락("좋아, 그렇게 해") / **보류 후 반영**("나중에 정하자"고 했는데 코드에 들어감) / AI 단독으로 구분합니다. 시제품으로 3턴 개발 대화를 분석했더니 결정 12개 중 8개가 포괄 수락, 3개가 AI 단독이었고 근거 인용 19개는 모두 원문과 일치했습니다. AI 작성 비율, 위험 코드(결제·DB 쓰기·인증), AI가 기존 테스트의 기대값을 바꾼 경우도 함께 기록합니다.
- **측정과 상환:** 위험 코드 중 사람이 정하지 않은 결정(보류 후 반영 → AI 단독 → 포괄 수락 순)부터 질문 3개를 냅니다. 코드만 보면 바로 읽히는 사실은 묻지 않습니다. 답은 질문마다 정한 핵심 포인트를 충족했는지로 판정하고, 놓친 포인트만 근거 원문과 함께 짧게 설명한 뒤 다른 질문으로 다시 확인합니다.
- **실행 방식:** AI 판단은 Claude Code CLI의 비대화형 모드로 처리해, 이미 쓰는 Claude Code 구독 한도 안에서 별도 API 키·과금 없이 동작합니다. 모델 호출은 인터페이스 하나로 분리해, OpenAI 호환 API(사내 OSS 모델 등)로 작업별로 바꿀 수 있게 설계합니다. 시연은 같은 화면을 보장하기 위해 리허설 때 받은 실제 응답을 재생하는 리플레이 모드로 합니다.

## 3. 해커톤 2일 동안 구현해 보고 싶은 주요기능은 무엇인가요?

1. **결정 근거 추출과 "정하지 않은 결정" 찾기:** 개발 대화와 코드 변경에서 결정·이유·버린 대안·결정 주체를 근거 원문과 함께 뽑아 함수에 연결합니다. "좋아"로 넘기거나 "나중에"로 미뤘는데 코드에 들어간 결정은 따로 표시하고, 보류했던 사용자 발화를 함께 보여 줍니다. 원문에 없는 이유는 지어내지 않고 "기록에 근거 없음"으로 표시합니다.
2. **"내가 모르는 내 코드" 지도:** 함수별 이해 상태(미측정·이해·보완 필요·재확인 필요)를 색과 상태명으로 보여 주고 위험 함수에 배지를 붙입니다. 단순 이해 커버리지와 위험 가중 이해 커버리지를 나란히 보여 "전체로는 높은데 결제 코드는 낮다"는 차이를 드러냅니다.
3. **테스트 변경 감지:** AI가 기존 테스트의 기대값을 바꾸면 "이 테스트는 원래 어떤 상황을 막고 있었나요?"를 가장 먼저 묻습니다.
4. **이해도 측정과 맞춤 상환:** 필요할 때 언제든(작업을 마친 뒤, 리뷰나 인수인계 전) 질문 3개에 답하면 놓친 부분만 3분 안에 짧게 채워 주고, 다른 질문으로 다시 확인해 위험 가중 커버리지의 변화를 보여 줍니다.
5. **이해 만료:** 확인했던 함수의 코드가 바뀌면(구문 트리 해시 비교) 지도에서 해당 칸이 노란색으로 바뀌어 재확인이 필요하다고 알려 줍니다.

- **1차 범위:** Python 프로젝트와 Claude Code 개발 대화, 개인용. 시연은 비식별 결제 재시도 샘플 프로젝트로, 중복 결제를 막는 멱등성 키 결정과 미뤄 둔 타임아웃 값이 코드에 들어간 과정을 보여 줍니다.
- **구현 형태:** CLI와 로컬 DB(SQLite), 결과를 보여 주는 정적 웹 리포트.
- **이번 범위에서 제외:** 인수인계 파일 내보내기, 개발 중 실시간 질문, 리뷰 리허설, PR·Jira 연동, 팀 공유, 다른 언어, 시간 경과 기반 재확인 (7번 확장 계획 참고)

## 4. 이 아이디어의 주요 사용자는 누구이며, 어떤 기대효과가 있나요?

**주요 사용자**

- **1차:** 코드 에이전트로 혼자 또는 소수로 많은 양을 개발하는 개발자. 경력과 상관없이, 만드는 속도가 이해하는 속도를 앞지른 사람이 본인을 위해 쓰는 도구입니다. 실무 감각이 아직 없는 신입·직무 전환자는 같은 문제를 더 크게 겪습니다
- **2차:** 인수인계받는 사람, 신입 온보딩 담당자, 코드 리뷰어 (본인이 공유한 결정 기록만 조회하며, 개인의 이해 점수는 보지 않음)
- **확장:** AI로 개발한 결과물을 납품받는 고객사 (결정 기록을 인수인계 자료로 제공)

**기대효과**

- **아무도 정하지 않은 결정의 조기 발견:** "나중에"로 미뤘거나 "좋아"로 넘긴 결정이 결제·인증·데이터 변경 코드에 들어가 있으면 리뷰나 배포 전에 드러납니다. AI가 테스트 기대값을 바꿔 생기는 회귀도 함께 드러납니다.
- **리뷰 왕복 감소:** 작성자는 리뷰 전에 답을 준비하고, 리뷰어는 결정 근거를 바로 조회합니다.
- **AI 없이도 대응하는 팀:** 장애가 나거나 AI 서비스가 멈춰도 작성자가 동작과 수정 지점을 설명할 수 있습니다.
- **감독할 수 있는 개발자:** AI가 대신 짜면서 사라지던 이해와 학습 기회를 3분 확인으로 되살려, AI가 만든 결과를 계속 감독할 수 있게 합니다. 신입 온보딩에서는 결정 기록이 "이 코드가 왜 이렇게 됐는지"를 알려 주는 자료가 됩니다.
- **지식 보존:** "왜"가 근거와 함께 코드에 연결되고, 근거가 없는 부분은 "근거 없음"으로 남아 잘못된 기억이 전파되지 않습니다.
- **관리 지표:** 테스트 커버리지처럼, 코드 중 사람이 실제로 이해하는 비율을 위험도로 가중한 **"위험 가중 이해 커버리지"**를 보여 줍니다. 위험도 기반 부채 점수는 cdebt 등 기존 오픈소스에도 있으며, XHuman은 이를 "사람이 정하지 않은 결정"과 함께 보여 준다는 점이 다릅니다.

**측정 지표(안):** 상환 전후 커버리지 변화와 다음 날 다른 질문으로 한 재확인(단기 암기 효과 배제), 리뷰 질문에 바로 답한 비율, 보류 후 반영·포괄 수락·AI 단독 결정 중 사람이 확인한 비율, 결정 추출과 주체 분류의 정확도. 파일럿에서는 같은 사람에게 '요약만 읽기'와 'XHuman' 조건을 교차 적용하고, 조건을 모르는 리뷰어가 설명 품질을 채점해 비교합니다.

## 7. 제안해 주신 아이디어에 대해 추가로 언급하고 싶은 내용이 있으면 작성해 주세요.

- **기존 도구와의 차이:** 대화 보존 도구(Agent Note, Entire)는 대화를 커밋에 붙여 조회하게 해 주지만 사람의 이해는 확인하지 않습니다. 코드 기반 퀴즈 도구(cdebt, PR Guard 등)는 질문·상환·만료까지 지원하지만 대화 속 결정은 보지 않습니다. 개발 중·푸시 전 이해도 점검 도구(comprehension-check, Sphinx, Code Understanding Coach)는 변경된 코드나 기능을 보고 묻습니다. 이 중 comprehension-check만 세션 맥락으로 AI가 정한 결정을 묻고, Sphinx는 독립 채점을 위해 의도적으로 대화를 보지 않습니다. 어느 쪽도 대화 원문으로 결정을 검증하거나 "누가 정했는가"로 질문 순서를 정하지 않습니다. XHuman은 퀴즈·상환·만료를 기본 흐름으로 쓰되, **"좋아"로 넘기고 "나중에"로 미뤘는데 코드가 된 결정**을 대화 원문에서 찾아 먼저 묻는다는 점이 다릅니다.

- **관련 오픈소스 (이미 많습니다):** AI가 만든 코드를 사람이 이해하지 못하는 문제는 요즘 화두라, 같은 문제를 다루는 오픈소스가 이미 여럿 있습니다. 퀴즈·상환·만료·위험도 점수는 이미 있는 기능이고, XHuman은 그중 **사람이 정하지 않은 결정**만 좁혀서 다룹니다. (확인일 2026-11-10, 각 README 기준)

- **로컬 우선:** 대화 원본·답변·이해 상태는 개인 PC에만 저장하고 본인만 봅니다. 분석할 때는 대화와 코드 일부가 Claude Code로 전송되므로, 사내에서는 승인된 Claude Code 환경에서만 쓰고 비밀값을 가린 뒤 보냅니다. 평가 부담이 없어야 "모른다"를 솔직하게 답할 수 있으므로, 머지를 막는 관문이 아니라 본인용 코치로 동작하고 인사 평가에는 쓰지 않습니다.
- **축적과 확장:** 결정과 이해 기록은 쓸수록 쌓이고 코드 변경에 맞춰 갱신됩니다. 1차 결과(결정 추출·주체 분류 정확도, 다음 날 재확인 성적, 반복 사용 여부)를 확인한 뒤 본인이 검토한 결정 기록의 팀 공유, 인수인계 파일 내보내기(`xh export`: 본인이 검토한 결정·이유·버린 대안·근거 인용만 md로, 점수는 제외), PR 연동, 사내 OSS 모델, 다른 언어, 고객사 인수인계 자료 순으로 넓힙니다.

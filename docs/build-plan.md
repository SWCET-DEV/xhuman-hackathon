- [ ] `where claude`(Windows) 또는 `which claude`로 실행 파일이 `.exe`인지 `.cmd` 래퍼인지 적는다. `.cmd`면 프로그램이 JSON 스키마를 인자로 넘길 때 따옴표가 깨질 수 있다. 그 경우 2·3번이 스크립트로는 실패하고 손으로는 성공할 수 있으니 둘 다 해 보고 적는다(목요일 `claude_cli.py` 구현에 영향)

**① Claude 계정 4가지 (25분, 가장 중요. 지금까지의 검증은 모두 개인 계정에서 했다)**

- [ ] 나눠 준 Claude 계정으로 Claude Code 로그인. `claude --version`을 적는다(녹화본은 2.1.322, 더 높아도 된다)
- [ ] **1. 한 번 호출이 되는가:** `claude -p "ok" --output-format json` → JSON이 나오고 `is_error`가 false
- [ ] **2. 형식 지정이 되는가:** 아래 명령 → 결과에 `structured_output`이 있고 그 안에 `ok`가 있다. 걸린 시간을 적는다

  ```bash
  claude -p "ok라고만 답해" --model haiku --tools "" --no-session-persistence --setting-sources "" --output-format json --json-schema '{"type":"object","properties":{"ok":{"type":"boolean"}},"required":["ok"]}'
  ```

  Windows 명령 프롬프트(cmd)에서는 작은따옴표가 안 통한다. 스키마 부분을 `"{\"type\":\"object\",\"properties\":{\"ok\":{\"type\":\"boolean\"}},\"required\":[\"ok\"]}"`로 바꾼다(이 표기는 직접 실행해 확인하지 못했다. 안 되면 Git Bash나 PowerShell 7에서 위 명령을 쓴다). 따옴표 때문에 실패한 것과 기능이 없어서 실패한 것을 구분해 적는다
- [ ] **3. 모델을 고를 수 있는가:** 위 명령의 `--model haiku`를 `--model sonnet`으로 바꿔 한 번 더. 둘 다 되어야 한다(추출·질문은 sonnet, 채점·설명은 haiku)
- [ ] **4. 한도와 방식:** 구독 로그인인지 API 키인지, 사용량 한도가 얼마인지(Claude Code 안에서 `/status` 또는 `/usage`, 모르면 주최 측에 묻는다). 하루에 실제 AI 호출이 수십 번, 긴 입력은 한 번에 대화 기록 전체 정도라고 말하면 된다
- [ ] `--help`에 `--json-schema`, `--tools`, `--no-session-persistence`, `--setting-sources`가 모두 있는지

## 1. 시간표 (목 11/12 08:00~22:00, 금 11/13 08:00~13:00)

주최 측 확인(11/10): 구현은 목요일 08~22시, 필요하면 금요일 08~13시까지 할 수 있다. 발표자료는 목요일 22시 이후 집에서 만들 수 있다.

**판단: 금요일 오전은 기본 계획이 아니라 버퍼다.** 기본 계획은 목요일 22시에 시연 가능한 상태로 끝난다.

1. 발표자료는 목요일 밤에 목요일의 숫자와 캡처로 만든다. 금요일에 코드를 바꾸면 슬라이드 숫자와 화면 숫자가 어긋날 수 있다. 이건 시연에서 가장 치명적인 실수다.
2. 혼자 14시간 구현한 다음 날 아침에 바꾼 코드는 회귀 위험이 가장 크다. 그런데 발표 직전이라 고칠 시간이 없다.
3. 금요일까지 기본 계획에 넣으면 버퍼가 0이 된다. 목요일에 밀리는 일은 거의 확실하고, 그때 흡수할 곳이 사라진다.

**운영 규칙**

- **Codex는 고치지 않고 보고만 한다.** 보고는 차단·높음만 5개 이내, 항목마다 위치(파일:줄) / 재현 명령 / 기대 결과 / 실제 결과. 수정은 Claude가 하고, 같은 재현 명령으로 Codex가 다시 확인한다.
- **수정은 회당 20분까지.** 넘으면 고치지 않고 1.3 컷 라인으로 간다. 중간·낮음은 금요일 복구 목록에 적기만 한다.
- **폴더와 데이터를 나눈다.** worktree에서는 `pip install`을 하지 않는다(설치하면 Claude 쪽 `xh` 명령이 worktree 코드를 가리키게 된다). 대신 worktree 폴더에서 `python -m pytest -q`, `python -m xhuman <명령>`으로 실행한다. Codex는 단계 커밋으로 만든 별도 worktree에서 돌린다: `git worktree add ../xh-verify <커밋>`(다음 회차는 `git -C ../xh-verify checkout <커밋>`). Codex가 `xh`를 실행할 때는 `XHUMAN_HOME`을 별도 임시 폴더로 두고 `XHUMAN_REPLAY=1` 또는 `XHUMAN_BACKEND=fake`로만 실행한다. **Codex는 실제 `claude`를 부르지 않고, Claude 쪽 `~/.xhuman`(캐시 포함)을 건드리지 않는다.**
- **Codex 계정이 안 되면(S0 첫 5분에 확인):** V1~V3을 Claude Code 새 세션(이 대화의 맥락 없이)에 같은 프롬프트로 맡긴다. 독립성은 떨어지지만 구현 맥락이 섞이지 않는다. Codex를 Claude 장애 대체용으로 남겨 두기 위해 검증으로 한도를 다 쓰지 않는다.

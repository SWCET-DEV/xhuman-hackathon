## 현재 상태 (11/10 화 저녁 기준, 새 세션은 여기서 시작)

**오늘 정한 것**

- 차별점: 사람이 정하지 않은 결정("좋아"로 넘긴 포괄 수락, "나중에"로 미룬 보류 후 반영)을 대화 원문에서 찾아 먼저 묻는다. 약속은 "사람이 정하지 않은 결정을 내가 설명할 수 있게 만든다". 관련 오픈소스가 많다는 점은 기획서 7장 표와 발표 멘트로 밝힌다.
- 주요 사용자: 경력이 있어도 코드 에이전트로 혼자 방대하게 개발하는 본인. 인수인계·온보딩은 2차(결정 기록만 공유, 점수 비공개). 사용 시점은 "PR 전"이 아니라 "필요할 때".
- 반입: 프로토타입 코드는 반입 불가. md의 코드(SQL DDL, Python 인터페이스)는 표·문장으로 바꿨고, 재구현 규칙은 [contracts.md](contracts.md) 5장. 반입 목록과 주최 측 질문은 [carry-in.md](carry-in.md).
- 일정: 목 08~22시 기본 계획(20:30 동결), 금 08~13시는 버퍼(10:30 최종 동결). 발표자료는 목요일 밤 [slides-draft.md](slides-draft.md)의 자리만 채운다.
- AI 엔진: 오늘 저녁 모든 프롬프트는 Claude(`claude -p`)로 검증한다(지금 OpenAI API 접근 없음). 목요일에 250달러 크레딧이 실제로 있으면 C1 뒤 OpenAI 호환 백엔드를 `grade`에만 붙여 보고, 같은 답변의 판정이 Claude와 같을 때만 쓴다. 아니면 전부 Claude. 범위상 선택 항목 그대로.
- 프롬프트(11/10 저녁 기준): question-v0.7, grade-v0.5, repay-v0.5, extract는 그대로. 채점 검증 결정(구체적·단일 주장 포인트, 목적만 말한 답 미충족, 응용 재확인)과 "지시문에 시연과 겹치는 예시를 두지 않는다"(T0-6)를 반영했다. 인수인계 내보내기(`xh export`)는 다음 단계, 이번 범위 제외.

## 1. 시간표 (목 11/12 08:00~22:00, 금 11/13 08:00~13:00)

주최 측 확인(11/10): 구현은 목요일 08~22시, 필요하면 금요일 08~13시까지 할 수 있다. 발표자료는 목요일 22시 이후 집에서 만들 수 있다.

**판단: 금요일 오전은 기본 계획이 아니라 버퍼다.** 기본 계획은 목요일 22시에 시연 가능한 상태로 끝난다.

1. 발표자료는 목요일 밤에 목요일의 숫자와 캡처로 만든다. 금요일에 코드를 바꾸면 슬라이드 숫자와 화면 숫자가 어긋날 수 있다. 이건 시연에서 가장 치명적인 실수다.
2. 혼자 14시간 구현한 다음 날 아침에 바꾼 코드는 회귀 위험이 가장 크다. 그런데 발표 직전이라 고칠 시간이 없다.
3. 금요일까지 기본 계획에 넣으면 버퍼가 0이 된다. 목요일에 밀리는 일은 거의 확실하고, 그때 흡수할 곳이 사라진다.

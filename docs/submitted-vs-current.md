# 제출 기획서 → 현재 (11/10 비교)

제출한 기획서(사전 제출본)와 지금 계획의 차이다. 발표에서 바뀐 점을 먼저 밝히고, 제출본에서 약속한 것 중 빠지는 것은 이유를 함께 말한다. 제출본 원문과 개인 정보는 이 저장소에 두지 않는다.

## 1. 바뀐 점

| 항목 | 제출본 | 현재 | 이유 |
|---|---|---|---|
| 차별점 | AI 대화에서 사라지는 "왜"를 되살린다 | **사람이 정하지 않은 결정**("좋아"로 넘긴 것, "나중에"로 미룬 것)을 대화 원문에서 찾아 먼저 묻는다 | 제출 뒤 조사해 보니 "왜"를 묻거나 AI가 정한 결정을 묻는 오픈소스가 이미 있었다(comprehension-check 등). 남는 차이로 좁혔다 |
| 약속 | AI가 짠 코드를 3분 만에 내가 설명할 수 있는 코드로 | 사람이 정하지 않은 결정을 필요할 때 3분 만에 내가 설명할 수 있게. 모든 코드를 이해시키겠다고 약속하지 않음 | 에이전트 속도로는 다 이해할 수 없다(Anthropic "감독의 역설") |
| 결정 주체 | 사람 지시, AI 단독 등 | 사람 지시 / AI 제안 후 구체적 수락 / 포괄 수락 / **보류 후 반영** / AI 단독 | 보류 후 반영이 새 차별점의 중심 |
| 질문 우선순위 | 위험하고 AI가 단독으로 결정한 곳부터 | 위험 코드 중 보류 후 반영 → AI 단독 → 포괄 수락 순 | 같은 방향, 보류를 맨 앞에 추가 |
| 1차 사용자 | AI 코딩 도구를 쓰는 개발자, 특히 주니어 | 코드 에이전트로 혼자 방대하게 개발하는 개발자(경력 무관). 신입은 같은 문제를 더 크게 겪음 | 만든 사람 본인의 문제에서 출발 |
| 2차 사용자 | 코드 리뷰어와 팀 리더 | 인수인계받는 사람, 온보딩 담당자, 리뷰어. **결정 기록만** 보고 점수는 보지 않음 | "팀 리더"는 점수를 본다는 인상을 줌. 결과는 본인만 본다는 원칙과 맞춤 |
| 측정 시점 | PR을 올리기 전 | 필요할 때 언제든(작업 뒤, 리뷰·인수인계 전) | 관문이 아니라 본인용 도구 |
| 질문 수 | 3개 | 3개(같음) | |
| 점수 예시 | 40% → 85% | 시연 세션으로 다시 계산(예: 위험 가중 27% → 64%). 단순·위험 가중 두 숫자를 함께 보여 줌 | 실제 숫자만 쓴다 |
| 실행 방식 | Claude Code CLI 헤드리스, 별도 API 비용 없음, 사내 OSS로 전환 가능 | 같음. OpenAI 호환 API(사내 OSS 등)는 작업별 선택. 시연은 리플레이 모드 | |
| 기존 기능과의 차이 | diff 퀴즈는 "무엇"을 묻는 관문, recap·메모리는 다른 문제 | 관련 오픈소스 8종을 기획서 7장 표로 공정하게 비교. 퀴즈·상환·만료·위험 점수는 이미 있다고 인정 | 제출본의 "다른 도구는 '무엇'만 묻는다"는 설명은 조사 결과 정확하지 않았음 |

## 2. 제출본 기능별 상태

| 제출본 기능 | 이번 해커톤 | 발표에서 할 말 |
|---|---|---|
| ① 이해 데이터 자동 축적(결정, 작성 출처, 위험, 테스트 변경) | 만든다. 테스트 변경 감지는 컷 1순위 | "자동"은 세션 기록을 `xh ingest`로 읽는 방식(훅 자동 실행은 아래 참고) |
| ② 이해도 측정 + "내가 모르는 내 코드" 지도 | 만든다. 지도는 정적 HTML 리포트(최소 버전 필수) | 색은 초록·빨강에 더해 노랑(만료)·회색(미측정) |
| ③ 맞춤 상환 + 재측정 | 만든다. 재확인 채점은 컷 3순위 | |
| ④ 리뷰 리허설 | **핵심 흐름에 합쳤다**(별도 기능은 다음 단계) | "리뷰 리허설은 핵심 흐름과 겹쳐서 하나로 합쳤습니다." 이유: ① 리허설(AI가 리뷰어처럼 묻고 보완점을 알려 줌)은 "정하지 않은 결정을 묻고 → 채점하고 → 모르는 부분만 채우는" 흐름과 하는 일이 같고, 핵심 흐름이 더 좁고 근거가 분명하다. ② 리허설은 "PR 직전"을 전제로 한 기능인데, 지금은 "필요할 때" 쓰는 도구로 바꿨다 |
| ⑤ 이해 만료 | **만든다.** 목요일 17:15~17:45(30분), 시연 장면 5에서 함수 한 줄을 고치면 지도 칸이 노랑으로 바뀜. 컷 2순위지만 제출본 약속이고 비용이 작아 컷되면 금요일 복구 창에서 가장 먼저 살린다 | 컷되면 "설계·테스트는 있고 시연에서 뺐다"고 말한다 |
| 간단한 웹 화면 | 정적 HTML 리포트 | |
| Claude Code 훅으로 자동 실행 | **뺐다**(SessionEnd 훅) | "훅 입력 필드를 검증하지 못했고, 필요할 때 실행하는 방식으로 바꿨다" |
| 다른 언어·지라 제외 | 같음 | |
| 결과는 본인만, 공유는 동의할 때만 | 같음. 인수인계 내보내기(`xh export`, 결정 기록만)는 다음 단계 | |
| 측정 지표: 상환 전후 점수, 리뷰 질문 즉답률 | 상환 전후 점수만 시연. 즉답률·다음 날 재확인은 다음 단계 | 맞게 답한 것이 이해의 증명은 아니라고 먼저 말한다 |

**심사위원이 확인할 수 있는 약속:** ④ 리뷰 리허설과 훅 자동 실행은 빠지므로 발표에서 먼저 말한다. ⑤ 만료와 ① 테스트 변경 기록은 제출본에 있으므로 가능하면 금요일 복구 창에서라도 살린다(build-plan 1.2).

# 리포트 화면 설계 (`xh report`)

정적 HTML 1장. 서버 없음, 외부 리소스 없음(CSS·JS 인라인). 데이터는 생성 시점에 HTML 안에 JSON으로 넣는다. 프로젝터에서 보이도록 기본 글자 18px 이상, 밝은 배경.

## 1. 레이아웃

```
┌──────────────────────────────────────────────────────────────────┐
│ XHuman · demo-payment                         2026-11-xx 14:02   │
├──────────────────────────────────────────────────────────────────┤
│  위험 가중 이해 커버리지   27%        단순 커버리지   60%           │
│  ███░░░░░░░                          ██████░░░░                   │
│  결정 12 · 보류 후 반영 1 · 포괄 수락 7 · AI 단독 3 · 사람 지시 1   │
├───────────────────────────────┬──────────────────────────────────┤
│ 이해 지도                      │ 단위 상세                         │
│                               │                                  │
│ payment/retry.py              │ charge_with_retry   [결제][위험 높음]│
```

## 2. 색 규칙

| 상태 | 색 | 조건 |
|---|---|---|
| 이해 | 초록 `#2e7d32` | 최근 valid 기록 `understood` |
| 부분 | 연두 `#9ccc65` | `partial` |
| 모름·미측정 | 빨강 `#c62828` | `unknown` 또는 기록 없음 |
| 만료 | 노랑 `#f9a825` | 해시 변경으로 `expired` |
| 대상 아님 | 회색 `#9e9e9e` | AI 작성 비율 < 0.3 |

색만으로 구분하지 않는다. 각 칸에 상태 글자(이해/부분/모름/만료)를 같이 쓴다.

## 3. 배지

| 배지 | 표시 |
|---|---|
| 위험 | `결제`, `DB 쓰기`, `인증` + 위험 높음 |
| 결정 주체 | 사람 지시(회색), AI 제안 수락(파랑), 포괄 수락(주황), AI 단독(빨강), 보류 후 반영(보라 `#6a1b9a`, 맨 앞에 정렬). 보류 후 반영은 상세에 사용자의 보류 발화를 ✓ 인용으로 함께 보여 준다 |
| 확신 낮음 | 결정 옆 `확인 필요` |
| 테스트 변경 | 단위 옆 `⚠ 변경`, 상세에 before/after |

## 4. 동작

- 지도에서 단위를 클릭하면 오른쪽 상세가 바뀐다(인라인 JS). 첫 화면은 우선순위가 가장 높은 단위가 선택된 상태.
- 정렬: 파일 순 → 줄 순. 상단 요약 아래 "이해 부채 상위 5개" 목록은 접어 둔다.
- 시연 장면 2·5에서 쓰므로 새로고침만으로 갱신되게, 파일 경로를 고정한다(`~/.xhuman/report/index.html`).

## 5. 최소 버전 (필수, build-plan S4 ①)

1~4장은 꾸민 버전이다. 목요일에는 아래 최소 버전을 먼저 만들고, 꾸미기는 목요일 동결 전 버퍼가 남거나 금요일 복구 창에서만 얹는다.

- JS 없음. 한 페이지에 위에서 아래로: 제목 → 커버리지 두 숫자 → 결정 주체별 개수(배지) → 단위 표 → 단위별 결정 목록(전부 펼침)
- 단위 표 열: 파일 · 함수 · 상태(색 칸 + 글자) · 위험 배지 · AI 작성 비율 · 테스트 변경 ⚠
- 색 규칙(2장)과 배지(3장)는 최소 버전에서도 그대로 쓴다. 색만으로 구분하지 않는다
- 글자 18px 이상, 밝은 배경. 캡처와 프로젝터 가독성 기준은 꾸민 버전과 같다
- 꾸미기는 이 HTML에 레이아웃과 JS만 더한다. 데이터 구조와 문구를 바꾸지 않아야 캡처·대본이 흔들리지 않는다

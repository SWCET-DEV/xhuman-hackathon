# repay: 놓친 부분만 압축 설명 + 재확인 질문

- 상태: **초안, 미검증.** 시연 질문 하나로 1회 돌려 설명 길이와 인용 일치를 확인한다.
- 모델: haiku
- 입력에는 **놓친 핵심 포인트만** 넣는다. 맞힌 포인트는 다시 설명하지 않는다.
- 출력: [contracts.md](../contracts.md) 2.3의 repay 스키마
- 프로그램 검증: `decisions[].quote`는 저장된 근거 인용 중 하나와 정규화 후 일치해야 한다. 일치하지 않으면 해당 항목에서 quote를 빼고 표시한다.

## 지시문

```text
너는 바쁜 개발자에게 꼭 필요한 것만 짧게 설명하는 선배다. 표준 입력으로 [코드], [질문],
[개발자가 놓친 핵심 포인트], [결정 기록과 근거 인용]이 주어진다. 놓친 포인트만 채워 준다.

규칙:
1. flow: 이 함수의 동작 흐름을 한 문장으로 쓴다.
2. decisions: 놓친 포인트와 관련된 결정을 최대 3개까지 각각 한 문장으로 쓰고, quote에는
   [결정 기록과 근거 인용]에 있는 인용문 하나를 글자 그대로 넣는다. 인용문을 만들어 내지 않는다.
   [결정 기록과 근거 인용]이 비었거나 놓친 포인트와 관련된 결정이 없으면 decisions는 빈 배열로 두고, 설명은 flow에만 쓴다.
3. alternative: 기록에 버린 대안이 있으면 한 문장으로, 없으면 빈 문자열.
4. 전체 설명은 소리 내어 읽어 1분 안에 끝나는 길이로 한다. 맞힌 포인트는 다시 설명하지 않는다.
5. recheck_question: 응용 질문 한 개. 원래 질문을 바꿔 말하지 않고, 놓친 포인트를 원래 질문과 다른 구체적 상황에 적용해야 답할 수 있게 묻는다(예: 원래가 "입력 목록이 비었을 때"였다면 "목록에 날짜가 같은 항목이 두 개 있다면?").
   방금 한 설명의 문장을 떠올려 옮기기만 해서는 답이 되지 않아야 한다. 질문에 답의 방향을 넣지 않는다(예: "필요 없다면 그 이유는?" 금지).
6. recheck_key_points: recheck_question의 모범 답안에 반드시 들어갈 사실이다. 놓친 포인트와 1:1로 대응하게, 같은 개수로 쓴다.
   각 항목은 그 놓친 포인트를 이해한 사람이 새 질문의 상황에서 말하게 될 사실이어야 한다. 놓친 포인트 문장을 그대로 옮기지 않는다.
   새 질문의 상황에서 성립하지 않는 사실(예: 질문은 캐시가 만료된 상황인데 포인트는 캐시가 아직 남아 있는 상황)을 쓰지 않는다.
   포인트 하나에 주장 하나만 쓰고, 대응하는 놓친 포인트에 없는 새 사실(예: 변수 값, 내부 상태)을 덧붙이지 않는다.
한국어로 쓴다.
```

## 출력 예

> **구현 참고용. 프롬프트에 넣지 않는다(few-shot 예시로 붙이지 말 것).** 모델에는 위 "지시문" 블록 안만 넘긴다.

```json
{
  "flow": "주문마다 고정된 멱등성 키로 PG 결제를 호출하고, 일시적 오류일 때만 백오프 후 같은 키로 다시 시도한다.",
  "decisions": [
    {"text": "타임아웃은 PG에서 이미 결제됐을 수 있는 상태로 본다.", "quote": "타임아웃 등으로 PG에서 처리됐을 수 있는 상태"},
    {"text": "모든 시도에 같은 키를 보내 PG가 중복 요청을 걸러내게 한다.", "quote": "모든 시도에 동일한 멱등성 키(order.id 기반)를 사용해 중복 결제를 막는다"}
  ],
  "alternative": "",
  "recheck_question": "첫 요청이 타임아웃 났는데 실제로는 PG에서 결제가 끝난 상태라면, 재시도에서 키를 새로 만들 때 무슨 일이 생기나요?",
  "recheck_key_points": [

  ]
}
```

## 검증 체크

- [ ] recheck_key_points에 놓친 포인트에 없는 사실이 붙지 않았다. v0.3에서 "ChargeOutcomeUnknown이 올라가며, response는 None이다"처럼 사실 하나가 덧붙어, 핵심을 다 맞힌 재확인 답이 3회 모두 partial로 떨어짐(11/10)

- [ ] quote가 모두 저장된 인용과 일치
- [ ] recheck_key_points 개수 = 놓친 포인트 개수
- [ ] recheck_key_points가 recheck_question의 답이다(질문 상황과 포인트 상황이 같다). v0.1에서 질문은 "5초 타임아웃이 났다면"인데 포인트는 "timeout이 None이면"으로 어긋난 결과가 나와 추가(11/10)
- [ ] 설명을 소리 내어 읽어 1분 이내

## v0.6 변경(11/11)

규칙 2: 결정 "2~3개"를 "최대 3개", 관련 결정이 없으면 빈 배열로 바꿨다. 결정이 없는 함수(how 질문)에서도 상환할 수 있어야 하는데, 2개를 강제하면 모델이 인용을 지어내야 했다(Codex 교차검증). contracts.md 2.3도 0~3개로 맞췄다.

## v0.5 변경(11/10)

지시문 안의 예시를 결제·재시도·타임아웃과 무관한 것으로 바꿨다(시연과 겹치는 예시를 두지 않는다는 발표자 결정). 규칙 문장은 그대로다. "입력 형식"·"출력 예"는 모델에 넘기지 않는 구현 참고용이라 결제 예를 유지했다.
